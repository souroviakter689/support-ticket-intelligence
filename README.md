# 🤖 AI-Powered Support Ticket Intelligence Platform

An AI-powered support ticket retrieval system that combines **Semantic Search, TF-IDF, and Hybrid Information Retrieval** to identify and rank relevant banking-related queries.

🚀 **Live Demo:** [Launch the Application](https://support-ticket-intelligence-omoxhwqwjukebnterbjurk.streamlit.app/)

📂 **GitHub Repository:** [View Source Code](https://github.com/souroviakter689/support-ticket-intelligence)

## 📌 1. Project Overview

Customer support systems often contain large collections of queries describing similar problems in different words. Traditional keyword-based search may fail to identify relevant queries when users express the same issue differently.

This project implements an AI-powered retrieval system that combines semantic understanding with lexical matching to retrieve relevant banking-related queries.

The system uses sentence embeddings generated by Sentence Transformers, TF-IDF representations, and cosine similarity to calculate relevance scores. A hybrid ranking strategy combines these signals to produce ranked search results.

The project also includes K-Means clustering artifacts, a FastAPI implementation, and Docker configuration for containerization.

## 🎯 2. Project Objectives

## 🧠 4. Methodology

The system combines semantic similarity and lexical similarity to rank relevant queries.

### 4.1 Semantic Embedding

The pretrained Sentence Transformers model:

`sentence-transformers/all-MiniLM-L6-v2`

converts text into numerical sentence embeddings.

The model produces embeddings with a dimension of **384**, allowing queries to be compared in a shared vector space.

### 4.2 Semantic Similarity

The system compares the query embedding with precomputed query embeddings using cosine similarity.

Semantic similarity helps identify queries that express related meanings, even when they use different words.

### 4.3 TF-IDF-Based Retrieval

TF-IDF represents textual information according to the importance of terms in the corpus.

The fitted TF-IDF vectorizer transforms the incoming query into a sparse numerical representation. Cosine similarity is then used to measure lexical similarity against the stored TF-IDF representations.

### 4.4 Hybrid Retrieval

The semantic and TF-IDF similarity scores are combined using a weighted formula.

**Hybrid Score = α × Semantic Similarity + (1 − α) × TF-IDF Similarity**

The current configuration uses:

* Semantic similarity weight: **0.9**
* TF-IDF similarity weight: **0.1**

Therefore:

**Hybrid Score = 0.9 × Semantic Similarity + 0.1 × TF-IDF Similarity**

This configuration prioritizes semantic similarity while retaining lexical matching as an additional retrieval signal.

### 4.5 Result Ranking

After calculating hybrid scores, the system ranks the available queries and returns the highest-scoring results.

Users can explore the retrieved text and available metadata, including intent category, similarity scores, and cluster assignments.

### 4.6 K-Means Clustering

The project includes a fitted K-Means model and saved cluster assignments.

The current configuration specifies **77 clusters**. This is a clustering configuration and should not be interpreted as proof that the discovered clusters correspond perfectly to the dataset's 77 original intent categories.

## 📈 10. Results and Evaluation

The project implements a hybrid retrieval pipeline that combines semantic and lexical similarity.

The current configuration gives semantic similarity a weight of 0.9 and TF-IDF similarity a weight of 0.1.

However, configuration values alone do not establish retrieval effectiveness. A rigorous evaluation should compare hybrid retrieval against semantic-only and TF-IDF-only baselines using labelled relevance judgments.

### Recommended Evaluation Metrics

| Metric                     | Purpose                                                         |
| -------------------------- | --------------------------------------------------------------- |
| Precision@K                | Measures the proportion of retrieved results that are relevant. |
| Recall@K                   | Measures the proportion of relevant items retrieved.            |
| Mean Reciprocal Rank (MRR) | Evaluates the rank of the first relevant result.                |
| NDCG@K                     | Evaluates ranking quality while accounting for relevance.       |

**Experimental reporting:** Actual performance metrics should be added after running and verifying the corresponding evaluation experiments. No unverified accuracy, precision, or retrieval score is claimed here.

**Endpoint:** `GET /health`

Intended to return the API health status and relevant retrieval configuration.

**Endpoint:** `POST /search`

Accepts a search query and the requested number of results, then returns ranked search results.

The currently deployed Streamlit application performs retrieval directly within the Streamlit app and does not require a separately deployed FastAPI server.
